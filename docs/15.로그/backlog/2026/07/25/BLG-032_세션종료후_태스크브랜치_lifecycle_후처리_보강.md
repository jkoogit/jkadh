# BLG-032 세션 종료 후 태스크 브랜치 lifecycle 후처리 보강

> 상태: Open

## 1. 내용

세션 종료 성공 후 로컬 `main` 전환과 병합된 현재 세션 태스크 브랜치 정리 절차를 보강한다. 로컬 브랜치 정리는 안전조건 충족 시 기본 후처리로 수행하고, 원격 브랜치 삭제는 명시 승인으로 분리한다.

## 2. 발생 배경

세션 019에서 Issue 종료, 세션 PR 머지, `dev/stg/main` 승급과 HCP complete 전환은 성공했지만 현재 checkout이 종료된 태스크 브랜치에 남았고, 두 태스크의 원격 브랜치도 유지됐다. 현행 Harness는 PR merge에 `--delete-branch=false`를 사용하며 session close 이후 checkout·cleanup 단계를 제공하지 않으므로 같은 상태가 반복될 수 있다.

## 3. 기대 효과

- 다음 세션을 항상 최신 `main`에서 시작할 수 있다.
- 병합 완료 브랜치와 진행 중 브랜치를 안전하게 구분한다.
- 원격 삭제 권한을 명시적으로 유지하면서 불필요한 브랜치 누적을 줄인다.
- cleanup 실패가 이미 완료된 세션 결과를 훼손하지 않도록 복구 근거를 남긴다.

## 4. 처리 기준

- 관련 PR이 `MERGED` 상태인지 확인한다.
- PR merge commit이 `origin/main`에 포함되는지 확인한다.
- 해당 head branch에 열린 PR이 없는지 확인한다.
- tracked 작업트리가 clean인지 확인하고 `.hcp/` runtime은 별도로 취급한다.
- 브랜치가 현재 세션 HCP task에 등록된 소유 브랜치인지 확인한다.
- 세션 완료 후 로컬 `main` checkout과 로컬 태스크 브랜치 정리를 기본 후처리로 수행한다.
- 원격 브랜치 삭제는 별도 명시 승인 또는 전용 suffix가 있을 때만 수행한다.
- cleanup 실패 시 세션 상태를 되돌리지 않고 실패 브랜치, 통과한 조건, 남은 action을 recovery report로 기록한다.

## 5. 제외 범위

- 과거 전체 브랜치의 일괄 삭제
- 열린 PR 또는 미승급 태스크 브랜치 삭제
- 사용자 변경이 남은 브랜치의 강제 삭제
- 원격 브랜치의 기본 자동 삭제
