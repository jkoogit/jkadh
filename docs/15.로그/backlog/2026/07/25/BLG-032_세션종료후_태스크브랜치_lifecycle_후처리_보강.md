# BLG-032 세션 종료 후 태스크 브랜치 lifecycle 후처리 보강

> Backlog ID: BLG-032
> 상태: Deferred
> 유형: HCP
> 생성일: 2026-07-25
> 처리시점: 정기 점검 시
> 우선순위: Medium
> 의존 대상: 후처리 누락으로 다음 태스크가 차단되는 evidence
> 출처: 세션 019 사후 검증
> 연결 Issue: [#138](https://github.com/jkoogit/jkadh/issues/138)
> 연결 PR: -
> 해결 문서: -

## 1. 내용

세션 종료 성공 후 로컬 `main` 전환과 병합된 현재 세션 태스크 브랜치 정리 절차를 보강한다. 로컬 브랜치 정리는 안전조건 충족 시 기본 후처리로 수행하고, 원격 브랜치 삭제는 명시 승인으로 분리한다.

## 2. 발생 배경

세션 019에서 Issue 종료, 세션 PR 머지, `dev/stg/main` 승급과 HCP complete 전환은 성공했지만 현재 checkout이 종료된 태스크 브랜치에 남았고, 두 태스크의 원격 브랜치도 유지됐다. 현행 Harness는 PR merge에 `--delete-branch=false`를 사용하며 session close 이후 checkout·cleanup 단계를 제공하지 않으므로 같은 상태가 반복될 수 있다.

## 3. 기대 효과

- 다음 세션을 항상 최신 `main`에서 시작할 수 있다.
- 병합 완료 브랜치와 진행 중 브랜치를 안전하게 구분한다.
- 원격 삭제 권한을 명시적으로 유지하면서 불필요한 브랜치 누적을 줄인다.
- cleanup 실패가 이미 완료된 세션 결과를 훼손하지 않도록 복구 근거를 남긴다.

## 4. 처리 기준

- 관련 PR이 `MERGED` 상태인지 확인한다.
- PR merge commit이 `origin/main`에 포함되는지 확인한다.
- 해당 head branch에 열린 PR이 없는지 확인한다.
- tracked 작업트리가 clean인지 확인하고 `.hcp/` runtime은 별도로 취급한다.
- 브랜치가 현재 세션 HCP task에 등록된 소유 브랜치인지 확인한다.
- 세션 완료 후 로컬 `main` checkout과 로컬 태스크 브랜치 정리를 기본 후처리로 수행한다.
- 원격 브랜치 삭제는 별도 명시 승인 또는 전용 suffix가 있을 때만 수행한다.
- cleanup 실패 시 세션 상태를 되돌리지 않고 실패 브랜치, 통과한 조건, 남은 action을 recovery report로 기록한다.

현재 자동화는 보류하고 세션정리에서 다음 수동 후처리를 확인한다.

- 원격 `dev`, `stg`, `main` 정합성을 확인한다.
- tracked 작업트리가 clean이고 `.hcp/` runtime만 남았는지 확인한다.
- 현재 세션의 모든 HCP task가 `promoted`인지 확인한다.
- 최신 `origin/main`을 기준으로 로컬 `main`을 현행화하고 `main`으로 전환한다.
- 로컬 `dev`, `stg`에 고유 commit이 없을 때만 각 원격 추적 ref로 현행화한다.
- 현재 세션의 로컬 태스크 브랜치 삭제는 위 조건을 모두 통과한 경우에만 수행한다.
- 원격 태스크 브랜치는 자동 삭제하지 않는다.

자동화 재개 조건은 다음과 같다.

- 오래된 로컬 기준 브랜치 때문에 새 태스크가 잘못된 commit에서 시작한다.
- 종료된 태스크 브랜치 checkout 때문에 `#세션시작` 또는 `#태스크시작`이 차단된다.
- 수동 후처리 누락이 반복되어 잘못된 브랜치 commit, 중복 작업 또는 PR 충돌이 발생한다.
- 로컬 브랜치 누적으로 작업 브랜치 선택 오류가 실제 재현된다.
- 안전조건을 통과한 세션 소유 브랜치만 자동 정리할 수 있는 recovery 기준이 확정된다.

세션 019·020 evidence는 다음과 같다.

- 세션 019의 promoted 태스크 브랜치 2개와 세션 020의 promoted 태스크 브랜치 3개가 로컬·원격에 남아 있다.
- 승급 후 checkout이 직전 태스크 브랜치에 남고 로컬 `main`, `dev`, `stg`는 원격보다 6개 commit 뒤처졌다.
- 모든 후속 태스크는 최신 `origin/main`을 시작점으로 정상 생성되어 처리·승급됐다.
- 원격 `dev`, `stg`, `main`은 같은 commit으로 정렬되어 서비스 소스 정합성에는 영향이 없었다.

따라서 현재 상태는 정리 비용은 있지만 실제 태스크 차단은 아니므로 자동화하지 않고 `Deferred`를 유지한다.

## 5. 제외 범위

- 과거 전체 브랜치의 일괄 삭제
- 열린 PR 또는 미승급 태스크 브랜치 삭제
- 사용자 변경이 남은 브랜치의 강제 삭제
- 원격 브랜치의 기본 자동 삭제
